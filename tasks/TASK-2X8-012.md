## 1. STRATEGIC SPECIFICATION

### 1.1 Objective

Close blueprint **Phase 3D — Remaining Host / Memory Controls** on the retained
2x8 GAAS HPL-MxP stack with direct target-topology evidence.

TASK-2X8-011 closed Phase 3C with effectively full FP64 device residency:

~~~text
--fill-device 1
--fill-device-buffer-size 3048
host consumption ~= 0.004 GB/process
IR ~= 0.29 s

~~~

Mechanistically, this suggests that both remaining Phase-3D controls have
limited leverage:

- `--cuda-host-register-step` should matter mainly when meaningful FP64 data
  is host-resident/staged;
- `--call-dgemv-with-multiple-threads` changes host-side DGEMV work in the
  refinement path, whose current total time is already small.

However, the Human Leader explicitly wants direct experimental closure rather
than closing these controls only by inference.

This task therefore runs two **independent, fixed, bracketed sweeps** in one
clean same-allocation experiment:

~~~text
Stage A — cuda-host-register-step
  fixed DGEMV = 0

Stage B — call-dgemv-with-multiple-threads
  fixed cuda-host-register-step = 2048
~~~

There is **no interaction matrix**, no adaptive refinement, and no downstream
Phase-4 work.

- register-step sweeps were previously within noise in host-resident contexts;
- an older DGEMV sweep at N=491520 / OMP=8 / different ownership/residency
  found every tested nonzero value slower;
- a later bundled single-node record used DGEMV=15360 but changed several
  controls simultaneously, so 15360 was never isolated as beneficial.

The current 2x8 / OMP=4 / full-residency regime must therefore be tested
independently.

### 1.3 Strategic Questions / Hypotheses

#### Stage A — Host registration

Question:

> Does changing the host-registration batch size produce any measurable
> end-to-end, IR, or operational effect when FP64 data is already almost fully
> device-resident?

Hypothesis:

- differences should be at or near the local noise floor;
- LU should remain unchanged;
- any observable effect is more likely to appear in setup/registration or
  host-transfer behavior than in the LU critical path.

#### Stage B — DGEMV partition

Question:

> Under the current OMP=4, 4x4-row, full-residency regime, can a nonzero host
> DGEMV partition reduce refinement time enough to improve the final score?

Hypothesis:

- `0` may remain best because the total IR phase is already only ~0.29 s;
- nevertheless the current regime differs materially from the old DGEMV
  experiment, so a broad range is required to rule out a useful coarse
  partition.
