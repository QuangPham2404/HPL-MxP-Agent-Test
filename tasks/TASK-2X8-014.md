## 1. STRATEGIC SPECIFICATION

### 1.1 Objective

Optimize the HPL-MxP panel-broadcast policy on the retained 2x8 GAAS stack
after TASK-2X8-013 established that both communication families are already on
healthy GPU-direct fast paths.

This task varies **only**:

~~~text
--use-mpi-panel-broadcast
~~~

The experimental progression is deliberately bounded and sequential:

~~~text
Stage A — coarse sweep
    0 -> 25 -> 50 -> 75 -> 100
    with an opening and closing 0 control

Stage B — one automatically selected fine sweep
    5-point spacing around the useful coarse region
    with a fresh opening and closing 0 control

Stage C — finalist communication diagnostics
    1 required nonzero diagnostic clone when available
    + at most 1 mechanism-distinct secondary clone
~~~

The purpose is to answer:

> On a healthy 2x8 H200 multinode communication stack, what MPI/NCCL panel
> policy gives the strongest LU critical-path behavior, and what communication
> evidence explains the useful region or plateau?

The task must be scientifically adaptive **without becoming recursively
adaptive**. The coarse result selects exactly one fine window. The fine result
selects at most two diagnostic clones. There is no second refinement stage,
no recursive search around a numerical leader, and no Phase 4C chunk tuning.

### 1.3 Strategic Questions / Hypotheses

#### Question A — coarse policy shape

> Moving from panel policy 0 to 100, does LU performance show an NCCL-favored
> endpoint, an MPI-favored endpoint, an interior optimum, or a broad plateau?

The percentage is a scheduling policy, not a linear bandwidth dial. Do not
assume 50 is mathematically halfway between two performance endpoints.

#### Question B — local useful region

> Once the coarse shape is known, does one bounded 5-point-spaced sweep reveal
> a repeatable local region or plateau worth retaining?

The purpose of the fine stage is to resolve a **region**, not to manufacture an
exact percentage winner from sub-noise differences.

#### Question C — mechanism

> For the useful nonzero policy/policies, does the communication evidence show
> the expected MPI/NCCL substitution and a plausible change in fabric
> backpressure, rail use, or rank timing that accompanies any LU movement?

Hypotheses:

- IR should remain near the retained ~0.29 s regime; the main useful signal
  should be LU-side.
- Because both UCX and NCCL are already GPU-direct, any gain should come from
  panel readiness, collective scheduling, synchronization, progress, or
  overlap rather than merely enabling RDMA.
- Per-HCA `port_xmit_wait` and traffic-shape changes may help explain a
  performance difference but are not optimization objectives by themselves.
- A broad plateau is a valid successful result.

#### 1.6C. Stage A -> Stage B transition logic

The transition is mechanical and **tie-tolerant**. It chooses a region, not a
winner.

After all six coarse arms are available:

##### Step 1 — build the policy estimates

Use valid PASSED arms only.

For policy 0, form the midpoint of C0a/C0b separately for:

~~~text
LU GFLOP/s
overall GFLOP/s
~~~

The other coarse estimates are C1=25, C2=50, C3=75, C4=100.

##### Step 2 — establish transition tolerances

Define:

~~~text
LU_transition_tolerance
  = max(relative C0a/C0b LU-GFLOP/s spread, 0.5%)

score_transition_tolerance
  = max(relative C0a/C0b overall-GFLOP/s spread, 0.5%)
~~~

These tolerances exist only to select the next **window**. They are not
statistical confidence intervals and do not authorize a winner claim.

If the C0a/C0b spread exceeds the project's normal 2% materiality convention,
do not get stuck or repeat Stage A automatically. Use the observed wider
spread as the transition tolerance and flag the uncertainty.

If C0a/C0b differ by more than **5%** in LU GFLOP/s or overall GFLOP/s under
otherwise identical valid controls, stop before Stage B and hand back the
coarse evidence because adaptive refinement would no longer be meaningful.

##### Step 3 — form the LU-competitive set

Let `LU_best` be the highest valid coarse LU GFLOP/s.

Include a policy in set `T` when:

~~~text
LU(policy) >= LU_best * (1 - LU_transition_tolerance)
~~~

This deliberately treats near-equal LU points as one region.

##### Step 4 — use overall score only as a tie-breaker

Within `T`, find the best overall GFLOP/s and create set `S` containing
members within `score_transition_tolerance` of that best score.

Choose the fine-sweep anchor:

- if `S` has one member: anchor = that policy;
- if `S` has multiple members: anchor = median panel percentage of `S`,
  rounded to the nearest 5 percentage points; exact half-way cases round upward to the next 5-point value.

This prevents a tiny score difference from forcing an endpoint when several LU
policies are effectively tied.

##### Step 5 — choose exactly one predefined fine window

Use the anchor to select:

~~~text
anchor <= 15:
    candidates = 5, 10, 15, 20, 25

anchor >= 85:
    candidates = 80, 85, 90, 95, 100

otherwise:
    candidates = anchor-15, anchor-10, anchor-5,
                 anchor,
                 anchor+5, anchor+10, anchor+15
~~~

All candidate values must remain within 0-100. Policy 0 is supplied separately
by the fine-stage opening/closing controls and should not appear as a duplicate
candidate.

Examples:

~~~text
anchor 25 -> 10,15,20,25,30,35,40
anchor 40 -> 25,30,35,40,45,50,55
anchor 50 -> 35,40,45,50,55,60,65
anchor 75 -> 60,65,70,75,80,85,90
anchor 100 -> 80,85,90,95,100
~~~

If the whole coarse space is essentially flat, this logic naturally yields a
central representative window rather than repeatedly chasing whichever coarse
point is numerically highest.

Once the fine window is chosen, **do not reconsider it** during Stage B.

### 1.10 Strategic Analyst Notes

Interpret Phase 4B as a **policy-region** experiment.

The desired analytical progression is:

~~~text
coarse shape
   ->
local fine region
   ->
plateau / useful policy family
   ->
diagnostic mechanism evidence
   ->
Phase-4B retained representative(s)
   ->
Phase 4C chunk tuning only if still justified
~~~

Primary signal: LU.

The retained low IR means a panel-policy result that moves overall performance
without corresponding LU movement needs careful explanation. Conversely, a
clear LU improvement that is partially offset by IR should still be preserved
as a communication result rather than discarded mechanically.

The 4A panel=0 diagnostic already establishes:

~~~text
UCX AUTO -> rc_mlx5 + large-message zero-copy
NCCL -> IBext_v11 + 128/128 observed GDRDMA channels
all eight physical HCAs active
~~~

Therefore do not interpret a nonzero panel policy as "enabling fast MPI."
MPI is already on a healthy fast path. The question is whether moving panel
steps between NCCL and MPI changes readiness/overlap beneficially.

Preserve `port_xmit_wait` as an explanatory metric. A useful candidate that
also changes the stable 4A wait pattern may provide stronger mechanism
evidence, but a lower wait counter is not itself proof of a faster policy.

The component-test MPI/NCCL broadcast timing lines occur before matrix
generation and must not be treated as the LU communication-time breakdown.

Do not require a unique percentage. If neighboring fine points lie inside the
local drift envelope and have the same LU behavior, close on a plateau and
choose a representative later for simplicity/stability.
