## 1. STRATEGIC SPECIFICATION

### 1.1 Objective

Close blueprint **Phase 3C — Residency** on the retained 2x8 GAAS HPL-MxP
operating point before moving to the remaining Phase-3 host/memory controls or
Phase 4 communication.

The task must answer one bounded question:

> At the final retained geometry/runtime stack, does automatic full FP64
> residency (`--fill-device 1`) remain the best practical residency mode, or
> does a partial-residency `--Anq-device` setting under
> `--fill-device 0` improve the end-to-end work/time balance by trading GPU
> residency against LU and iterative-refinement cost?

Use ordinary phase timing and memory telemetry to expose the tradeoff. Record
LU time/rate, IR time, IR/LU share, final HPL-MxP score, correctness, and
host/device memory behavior for every scored arm.

This is a **residency-closure task**, not a new N search. It may select and
verify a residency policy/buffer region, but it must not reopen N, NB,
grid/order, placement, host runtime, communication, precision, kernel, DGEMV,
or scheduling.

### 1.3 Strategic Question / Hypotheses

Primary question:

> As `Anq-device` increases under `--fill-device 0`, how do FP64 residency,
> host staging, LU performance, IR cost, and final score move relative to the
> current full-fill control?

Hypotheses to test, not assume:

1. Increasing FP64 device residency should reduce host-side staging and IR
   time, but consume more GPU headroom.
2. LU should remain comparatively stable, but any LU movement must be measured
   because reduced workspace/headroom can still alter the end-to-end balance.
3. The current `--fill-device 1` control is expected to be competitive because
   TASK-010 already shows nearly zero host FP64 allocation and very small IR,
   but a partial-residency point may preserve similar IR while leaving more
   device workspace.
4. If full fill remains in the leading end-to-end region, Phase 3C should be
   closed by verifying that the current 3048 MB buffer lies in a safe plateau,
   not by squeezing VRAM toward a correctness cliff.
5. If a partial-residency policy materially wins, do not automatically reopen
   N inside this task. Preserve the evidence for the Strategic Analyst to
   decide E15 after execution.

attempting an unbounded fine search. Do not add intermediate or larger

variable in those arms. Record the effective setting.

One valid scored attempt per arm is sufficient.

##### Stage-A control-stability rule

Use F0/F1 only as a factual same-allocation bracket; do not infer a
campaign-level winner.

- If F0 and F1 differ by <=2.0% in end-to-end score and show the same
  qualitative LU/IR/memory regime, Stage A is stable enough for the bounded
  branch below.
- If F0/F1 differ by >2.0%, run **at most one** additional full-fill control
  F2 at 3048 MB.
- If F2 restores a coherent bracket, use the median full-fill score as the
  mechanical reference.
- If full-fill controls remain inconsistent by >2.0% or show materially
  different memory/correctness behavior, stop the scientific branch and hand
  the evidence back. Do not expand the sweep.

##### Stage-A bounded branch

After all valid Stage-A arms:

1. Identify the highest valid partial-residency A-arm and the stable
   full-fill reference.
2. If the best partial-residency arm is **>2.0% above** the full-fill
   reference in end-to-end score, and correctness/memory evidence is valid:
   - skip Stage B;
   - run one bounded confirmation pair:
     - repeat the selected partial-residency arm once;
     - repeat the full-fill 3048 MB control once;
   - then stop TASK-2X8-011 and hand the evidence back for analysis.
3. Otherwise, if full fill remains within the <=2.0% leading region and is
   valid, proceed to Stage B.
4. Invalid/OOM/correctness-failing points are boundary evidence and are never
   promoted or repeated for performance.

This branch is mechanical carry-forward only. Codex/workers must not declare
the final residency winner.
