## What was completed

- **Plan agreed with user:** 3 clean runs (completely free nodes) + 3 dirty
  runs (nodes with jobs), identical launch config to experiment 1, plus new
  instrumentation per the professor's suggestions (in-run host-load
  sampling, IB port counters, NCCL logs; exp1 affinity capture retained).
- **Scripts added** (local + GAAS via git): `debug-scripts/
  run_3x4_clean_dirty.pbs` (host-pinned, NCCL_DEBUG=INFO full, sampler
  start/stop), `debug-scripts/capture_node_alloc_v2.sh` (pre/post per-node
  capture: exp1 sections + IB counter snapshot, port state/rate, numastat,
  load/PSI, in-job pbsnodes co-tenant listing), `debug-scripts/
  sample_node_load.sh` (10 s per-node sampler: loadavg, /proc/stat,
  meminfo/vmstat, PSI-if-present, numastat, all mlx5 sysfs counters,
  per-GPU util/power/clocks; sentinel stop + tick failsafe).
- **Cluster findings:** GAAS nodes are partitioned by a `Qlist`
  queue-affinity resource — `gpu_as` can only use g06-g17; the g20-g25
  range (user's initial preference) belongs to `gpu_ded`/`gpu_aisg`/
  `gpu_free` and is unreachable from `gpu_as`. Recorded in README.
- **Runs (all PASSED, N=250k, 3x4):**
  - clean250k_v1.1/v2/v3 (jobs 60454/60458/60459; g14+g16 pristine + g10
    light co-tenant): 70,330/68,546/60,840 GFLOPS/GPU (+2005/+1952/+1721%
    vs original baseline).
  - dirty250k_v1/v2 (jobs 60461/60474; g11+g13 GPU-busy + g10): 2,772/
    2,891 GFLOPS/GPU (−17%/−13%) — slow mode reproduced deliberately.
  - dirty250k_v3 (job 60740; g13+g09 light co-tenants + g11 pristine,
    user-approved mixed composition): 40,356 GFLOPS/GPU (+1108%) —
    intermediate.
- **Failed attempts (evidence preserved, README records):**
  `clean250k_v1` (job 60453): host-pinned select omitted exp1's actual
  per-chunk `ncpus=48:mem=1000GB` → cgroup OOM kill, exit 137. Retried as
  v1.1 with corrected select.
  - qdel'd submissions (pre-authorized, reasons recorded): job 60449
    (pinned g22 = `gpu_ded` node, unreachable from `gpu_as` — Qlist
    discovery), job 60470 (g13's free GPUs taken by co-tenant job 60466
    between dirty v1 and v2).
- **Analysis highlights** (full detail + tables in resource-alloc
  `README.md`): degradation is a **dose-response continuum** (pristine
  60-70k → light 40k → heavy 2.8-2.9k GFLOPS/GPU), driven by **host-side
  co-tenant contention** (identical ≈42.5 GB IB bytes moved per node in
  all runs; ≈0 co-tenant fabric traffic; NCCL/UCX transport selection
  identical across runs), not CPU-cycle starvation, not placement mismatch
  (clean runs were fastest despite cross-NUMA allocations and 76-86%
  remote-memory fractions). An "idle" co-tenant still degraded
  host-memory phases (g11 RNG/MATGEN MAX in v1/v2 → MIN after it left in
  v3). One pristine node does not rescue a mixed job (v3 LU 2.3x clean).
- **Git:** commits `7b32df8`, `8d8ca7c`, `b52811b`, `c08b7bd`, `6b79468`;
  GAAS clone re-synced (78 evidence files verified byte-identical, remote
