## CRITICAL defect found and fixed (do not re-hit)

**PBS/Torque forces `OMP_NUM_THREADS = 96` (the allocated core count) at job
start and silently ignores a `qsub -v "OMP_NUM_THREADS=..."` override.**

The first sweep (jobs 52360–52381, 18 runs) was therefore **invalid**: every
"phase 1" run actually ran at 96 threads/rank, and the observed GFLOP/s
variation was pure node noise (correlated with node g16/g17 vs g18/g19, not with
OMP_NUM_THREADS). Those 18 invalid `.o`/`.e` files were deleted from GAAS and
local, and `metrics.csv` was reverted to the clean 103-row state (the invalid
rows were only ever staged locally, never committed).

Fix: pass the thread count under a **different** variable name (`OMP_NT`) and
re-export `OMP_NUM_THREADS` from it **after** `module purge`. `OMP_PLACES` and
`OMP_PROC_BIND` are NOT clobbered and pass through `qsub -v` unchanged.
