## Main findings

- **Working:** 8× ConnectX-7 400G IB up (host + container); full host RDMA
  stack (`mlx5_ib`, `ib_core`, `ib_uverbs`, `rdma_ucm`); container MPI is
  CUDA-aware (`opal_built_with_cuda_support=true`, `coll:cuda`, `btl:smcuda`,
  `pml:ucx`); container UCX exposes `rc_verbs`/`rc_mlx5`/`dc_mlx5` +
  `cuda_copy`/`cuda_ipc`; `nvidia_peermem` 580.126.20 is loaded.
- **Missing / the bottleneck:**
  1. `gdrdrv` GDR-Copy driver absent (no `/dev/gdrdrv`); container gdrcopy falls
     back to `UCX_GDR_COPY_BW=get_dedicated:250 MB/s` (should be tens of GB/s).
  2. UCX default remote-GPU memory domain is `cuda_cpy` (staging GPU→CPU→NIC),
     i.e. GPUDirect RDMA is effectively off — the direct cause of 0–26% GPU util
     and the LU-dominated profile.
  3. `nvidia_peermem` loaded but `refcnt=0` (never used, consistent with #2).
  4. Container MPI has no `openib` BTL (only self/smcuda/tcp/vader).
- Conclusion: inter-node path works mechanically, but GPUDirect RDMA is disabled
  (missing gdrdrv + cuda_cpy default selection).
